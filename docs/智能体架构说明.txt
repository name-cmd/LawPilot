================================================================================
        法信通 LawTrust — 智能体（Agent）架构说明
================================================================================
日期：2026-08-10
版本：1.0（随阶段八 8.4 / 8.5 落地同步）
关联文档：docs/项目改进指南.txt（8.4 任务调度器 / 8.5 工具调用式智能体）

一句话定位：
    可信智能体 —— AI 可自主调用工具，但每一步都被核验。

--------------------------------------------------------------------------------
一、任务分派流程图
--------------------------------------------------------------------------------

输入守卫（滥用拦截 / PII 脱敏 / 隐私确认）
  ↓
任务调度器（确定性规则分类，3 类任务 + 寒暄/通用直通）
  ├── 法律问答 ────→ 现有流水线不变（新增可选工具调用，模型自主决定）
  │                    └─ 需要工具 → 工具循环（检索法条 / 查询时效，上限 3 轮）
  ├── 合同审查 ────→ 文档优先 → 合同专用提示词 → 结构化风险清单
  │                    → 引用核验（含文档引文逐字比对）
  ├── 时效查询 ────→ 直查法律时效注册表 → 确定性结论 → 模型润色
  │                    → 标注「来源：法律时效注册表」（零 RAG 零核验）
  └── 寒暄 / 通用 ──→ 现状完全不变
      所有法律类管线出口 → 引用核验 + 六维可信评分闭环
      （时效查询除外：确定性数据，不核验）

核心形态：主管-专家。调度器是前台接待员（只负责分类与分派），各管线是
          专业窗口（内部完全复用现有模块），工具是员工手里的工具包。

--------------------------------------------------------------------------------
二、设计决策（每条附「为什么」）
--------------------------------------------------------------------------------

决策1：任务分类用确定性规则，不用大模型判断
  为什么：快（毫秒级正则匹配，不产生额外模型调用）、稳（行为可预期、
  可单测）、便宜（零 API 成本）、可解释（命中哪条规则一目了然，答辩
  可直接展示）、可回退（规则不命中一律落回法律问答，最坏等于现状）。

决策2：回退安全 —— 最坏情况等于现状
  为什么：任何误判都不允许比现状更差。分类置信度不足、规则未命中、
  工具循环出错，全部落回通用法律问答管线；「不退化」是智能体上线的
  底线，也是对比评测里「零回归」承诺的来源。

决策3：工具集收敛为 2 个（检索法条 / 查询时效）
  为什么：工具越多，模型选错、参数填错的概率越大，核验难度越高。
  赔偿计算、合同条款解析等工具可核验性弱，留待二期。2 个本地工具
  （向量库 + 注册表）覆盖「多法条交叉」与「时效确认」两个高频场景，
  足够支撑答辩演示叙事。

决策4：工具循环上限 3 轮，每轮决策 token 上限约 512
  为什么：防死循环、防费用爆炸。3 轮足够完成「检索 → 再检索 → 作答」
  的典型路径；轮次用尽自动兜底生成，绝不空白。

决策5：本地 7B 不启用函数调用
  为什么：7B 模型函数调用能力弱，强行开启输出不稳定。降级为提示词
  注入（「检索结果已由 RAG 提供，直接作答」），能力等价于现状，前端
  无感知，隐私模式的可信度不受影响。

决策6：不做模型自动路由
  为什么：与「用户可控」原则冲突。智能体只决定「怎么答」（走哪条
  管线、是否调工具），绝不决定「用哪个模型」——选哪个模型完全由
  用户决定，全链路透明可解释。

--------------------------------------------------------------------------------
三、答辩 Q&A 准备
--------------------------------------------------------------------------------

Q1：为什么不用大模型做任务分类？
A1：快、稳、便宜、可解释、可回退。分类是高频操作，用大模型判断每
    题都增加延迟与费用，且行为不可预期；确定性规则毫秒级完成，命中
    规则可单测、可展示，规则不命中还能安全回退到法律问答，不会比
    现状更差。

Q2：工具结果如何保证可信？
A2：工具只跑本地（向量库 + 注册表），零外部调用；工具结果只作模型
    的参考材料，不直接进入回答；最终回答的引用仍走引用核验 + 六维
    评分闭环，工具检索到的法条也会并入核验视野——工具让模型「看到
    更多」，但「说出口」的话一律过核验。

Q3：工具循环会不会死循环、烧钱？
A3：不会。循环有硬上限 3 轮，每轮工具决策的 token 上限约 512，超过
    即兜底生成；工具参数有长度上限并做控制字符清洗。费用可控，最坏
    情况是比普通回答多 1~2 次模型调用。

Q4：普通问题会不会变慢？
A4：模型认为不需要工具时，行为与现状完全一致（零成本零回归）；需要
    工具时多 1~N 次模型调用，延迟略增，换取的是「更准、更专业」。答辩
    承诺口径：更准、更专业、更可信，不承诺更快（缓存层另立阶段二，
    不在此范围）。

Q5：合同审查和普通问答有什么区别？
A5：合同审查走专用管线：文档解析优先 + 合同专用提示词 + 结构化风险
    清单输出（条款类型 / 风险点 / 法律依据 / 修改建议）+ 文档引文
    核验（回答引用文档原文的句子与上传文档逐字比对，防止模型编造
    条款）。普通问答套用通用模板，专业度与输出结构不同。

Q6：时效查询为什么不做检索和核验？
A6：因为它是确定性查询：结论（废止日期、替代法律）完全由本地注册表
    给出，模型只组织语言，无权编造时效事实。零 RAG 零核验换来秒级
    出结论——智能体选最优路径，而非什么都硬调大模型。

Q7：模型调用工具失败了怎么办？
A7：自动降级。工具循环任何一步异常（网络错误、参数错误、本地引擎
    不支持）都退回普通生成路径，等于现状，绝不返回空白或半截回答；
    失败的步骤仍记录进工具轨迹，可查可讲。

Q8：7 个模型都能用工具吗？
A8：只有 API 引擎启用函数调用（百炼全系支持），本地 7B 不启用。
    工具调用是「能力开放」而非「强制调用」——是否调用、调用什么由
    模型自主决策，普通问题下所有模型的行为与现状一致。不同模型的
    调用意愿有差异（如 glm-5.2 对多法条交叉问题主动调用工具，
    qwen3.7-plus 等一般不调），这是模型行为差异，不是缺陷。

四、效果对比评测结论
--------------------------------------------------------------------------------

评测方式：scripts/run_legal_trust_benchmark.py --mode agent（agent_compare
数据集 10 道单轮问答，默认模型 qwen3.7-plus；full 模式为对照组）。

| 指标 | full 模式 | agent 模式 | 说明 |
|---|---|---|---|
| 平均可信分 avg_trust_score | 83.29 | 83.2 | 持平（零回归） |
| 引用核验通过率 gold_citation_recall | 0.7 | 0.7 | 持平 |
| 平均工具调用数 avg_tool_calls | — | 0.0 | 见下方说明 |

结论：agent 模式开启工具能力后，10 道单轮问答的平均可信分与引用核验
通过率与标准模式持平（83.29 vs 83.2、0.7 vs 0.7），零回归。单轮问答
默认模型无需工具即可作答，因此工具调用数为 0，本次对比未体现工具
触发带来的增益（属预期内的可能结果，如实记录）。

工具触发数据如何获取：工具调用需要多步 / 查证类题目（如日期推算、
法条数目比对）或更主动调用工具的模型（实测 glm-5.2 可完整触发工具
链路）。评测脚本的 tool_call_count / avg_tool_calls 统计已就绪，
替换数据集或模型即可复用，无需改脚本。

演示脚本说明：工具轨迹现场演示请使用 glm-5.2 模型——实测
qwen3.7-plus / deepseek-v4-flash / kimi 在常规法律问题下不主动调用
工具（模型自主决策行为，属已知模型行为差异，不是缺陷）；glm-5.2 对
多法条交叉问题可完整触发工具链路（例如「工伤认定申请时效和劳动仲裁
时效分别是多少？」可观察到 9 次 agent_status 状态事件与 4 步
tool_trace 轨迹）。

--------------------------------------------------------------------------------
五、演示建议（现场脚本参考）
--------------------------------------------------------------------------------

推荐演示顺序（每个场景对应一条管线）：
1. 多模型切换：同题换 qwen3.7-plus / deepseek-v4-flash / glm-5.2
   对比回答（模型选择器，两级选择、Auto 跟随全局默认）；
2. 工具调用：切 glm-5.2，问多法条交叉问题（如「工伤认定申请时效和
   劳动仲裁时效分别是多少？」），观察「正在检索法条…→ 命中 N 条」
   状态行与详情面板「工具轨迹」tab 的逐步展开；
3. 合同审查：上传含试用期 / 工资条款的合同 txt，问「这份合同有什么
   风险条款？」，展示【合同风险清单】结构化输出与文档引文核验结果；
4. 时效查询：问「婚姻法现在还有效吗？」，展示「来源：法律时效注册表」
   标注与秒级出结论（对比普通问题的检索生成路径）。

答辩叙事主线：普通系统「模型说什么就是什么」；法信通是「模型想调
工具就调工具，想走哪条管线就走哪条管线，但说出口的每句话、引用的
每条法条、引用的每句文档原文，都必须过核验」——可信智能体。
