阶段二  问答缓存层 —— 避免重复计算，大幅降低延迟  ★新增
================================================================================

【目标】为法律问答流水线引入多层缓存机制，对相同/相似问题直接返回
        缓存结果，避免每次都执行完整的"检索→生成→核验→评分"流水线。

【预计耗时】2-3 天

【价值】
  - 相同问题再次提问：从 15-60 秒 → < 50ms（毫秒级返回）
  - 相似问题：语义匹配命中后可跳过 LLM 生成
  - GPU 资源节省：减少不必要的模型推理
  - 竞赛答辩时可展示"缓存命中率 X%"等性能数据

【现状分析】
  当前项目没有任何缓存机制：
    - 每次 POST /api/chat 都会重新执行完整流水线
    - 相同问题连续问两次，两次都要走检索+生成+核验
    - Embedding 计算结果不缓存（每次检索都重新计算查询向量）
    - 前端会话切换时需重新拉取（虽然存了 localStorage，但重新进入
      同一会话后翻看历史消息不会触发请求）

--------------------------------------------------------------------------------
2.1  缓存架构总览
--------------------------------------------------------------------------------

推荐三层缓存金字塔：：

                  ┌─────────────┐
                  │  L1: 精确   │  命中率 ~5%    延迟 < 1ms
                  │  问题缓存    │  (相同问题)
                  │  (内存 LRU) │
                  ├─────────────┤
                  │  L2: 语义   │  命中率 ~15%   延迟 < 50ms
                  │  相似缓存    │  (相似问题)
                  │  (内存+向量)│
                  ├─────────────┤
                  │  L3: 嵌入   │  命中率 ~60%   节省嵌入时间
                  │  向量缓存    │  (缓存 query embedding)
                  │  (磁盘/内存)│
                  └─────────────┘
                      ↓ 全部未命中
                  完整流水线（15-60s）

--------------------------------------------------------------------------------
2.2  L1 精确缓存：相同问题直接返回
--------------------------------------------------------------------------------

需要新建的文件：src/cache/exact_cache.py

实现方案：使用 Python 内置 lru_cache + 手动 TTL 管理

    import hashlib
    import time
    from collections import OrderedDict
    from typing import Optional

    class ExactQueryCache:
        """精确问题缓存 —— 相同 query+相同配置 → 直接返回缓存结果"""

        def __init__(self, max_size: int = 200, ttl_seconds: int = 1800):
            self._cache: OrderedDict[str, tuple[float, dict]] = OrderedDict()
            self.max_size = max_size
            self.ttl_seconds = ttl_seconds  # 默认 30 分钟过期

        def _make_key(self, query: str, use_rag: bool, enable_consistency: bool) -> str:
            """生成缓存 Key：MD5(query + 配置参数)"""
            raw = f"{query.strip().lower()}|rag={use_rag}|consistency={enable_consistency}"
            return hashlib.md5(raw.encode()).hexdigest()

        def get(self, query: str, use_rag: bool = True,
                enable_consistency: bool = False) -> Optional[dict]:
            key = self._make_key(query, use_rag, enable_consistency)
            if key not in self._cache:
                return None
            timestamp, result = self._cache[key]
            if time.time() - timestamp > self.ttl_seconds:
                del self._cache[key]
                self._cache.pop(key, None)
                return None
            # LRU: 移到末尾（最近使用）
            self._cache.move_to_end(key)
            return result

        def set(self, query: str, result: dict, use_rag: bool = True,
                enable_consistency: bool = False):
            key = self._make_key(query, use_rag, enable_consistency)
            self._cache[key] = (time.time(), result)
            self._cache.move_to_end(key)
            # 淘汰最久未使用的
            while len(self._cache) > self.max_size:
                self._cache.popitem(last=False)

        def clear(self):
            self._cache.clear()

        @property
        def hit_rate(self) -> float:
            """由外部调用者统计"""
            pass  # 命中率统计由 CacheManager 统一管理

在 web/backend/main.py 中集成：

    from src.cache.exact_cache import ExactQueryCache

    # 在模块顶部（与其他全局变量一起）

    # 在 /api/chat 端点开头插入缓存检查：
    @app.post("/api/chat", response_model=ChatResponse)
    def chat(req: ChatRequest):
        # --- 新增：L1 精确缓存检查 ---

            req.query,
            use_rag=req.use_rag,
            enable_consistency=req.enable_consistency,
        )
        if cached is not None:
            # 在响应中标记缓存命中（前端可显示"⚡缓存命中"）
            cached["cached"] = True
            return ChatResponse(**cached)
        # --- 原有逻辑 ---
        guard = _input_guard.check(...)
        # ...
        result = _pipeline.run(...)
        # --- 新增：存入缓存 ---

            _exact_cache.set(
                req.query, result,
                use_rag=req.use_rag,
                enable_consistency=req.enable_consistency,
            )

注意：
  - 安全拦截结果不缓存（滥用类问题每次都需要守卫检查）
  - 流式接口 /api/chat/stream 不适用精确缓存（流式的价值就是即时反馈）
  - 含文档上传的请求不缓存（文档内容每次可能不同）

2.3  L2 语义相似缓存：相似问题复用结果
--------------------------------------------------------------------------------

需要新建的文件：src/cache/semantic_cache.py

实现方案：将用户问题的 embedding 向量与缓存中问题的 embedding 做余弦相似度匹配

    import numpy as np
    from typing import Optional, List, Tuple

    class SemanticCache:
        """语义相似度缓存 —— 相似问题命中后返回已有答案"""

        def __init__(self, embedder, similarity_threshold: float = 0.92,
                     max_size: int = 500, ttl_seconds: int = 3600):
            self.embedder = embedder
            self.threshold = similarity_threshold
            self.max_size = max_size
            self.ttl_seconds = ttl_seconds
            self._entries: List[Tuple[np.ndarray, float, dict, str]] = []

        def search(self, query: str) -> Optional[dict]:
            """搜索语义相似的缓存结果"""
            if not self._entries:
                return None

            query_vec = self.embedder.embed_query(query)  # 复用现有嵌入模型
            query_vec = np.array(query_vec)

            best_score = -1.0
            best_entry = None
            now = time.time()

            for vec, timestamp, result, original_query in self._entries:
                # TTL 过期检查
                if now - timestamp > self.ttl_seconds:
                    continue
                # 余弦相似度
                sim = np.dot(query_vec, vec) / (
                    np.linalg.norm(query_vec) * np.linalg.norm(vec) + 1e-8
                )
                if sim > best_score:
                    best_score = sim
                    best_entry = result

            if best_score >= self.threshold and best_entry is not None:
                return best_entry
            return None

        def add(self, query: str, result: dict):
            """添加缓存条目"""
            vec = np.array(self.embedder.embed_query(query))
            now = time.time()
            self._entries.append((vec, now, result, query))
            # 淘汰最旧的条目
            while len(self._entries) > self.max_size:
                self._entries.pop(0)

        def clear(self):
            self._entries.clear()

注意：
  - L2 带来了额外的嵌入计算开销（query embedding），但远小于 LLM 推理
  - 配合 L3 嵌入缓存后，L2 的查询嵌入开销也可以消除
  - similarity_threshold 建议从 0.92 开始，根据实际效果调整

2.4  L3 嵌入向量缓存：避免重复计算 query embedding
--------------------------------------------------------------------------------

需要修改的文件：src/knowledge_base/embedder.py（新增缓存逻辑）

    import hashlib
    from functools import lru_cache

    class LawEmbedder:
        # ... 原有 __init__ 等 ...

        def embed_query(self, text: str, use_cache: bool = True) -> list:
            if use_cache:
                return self._embed_query_cached(text)
            return self._encode([text])[0].tolist()

        @lru_cache(maxsize=1000)
        def _embed_query_cached(self, text: str) -> tuple:
            """缓存单个查询的 embedding 结果（LRU 自动淘汰）"""
            vec = self._encode([text])[0].tolist()
            return tuple(vec)  # list 不可 hash，转 tuple 后可用 lru_cache

注意：
  - Python 的 @lru_cache 是线程安全的（GIL 保护），适合 FastAPI 同步端点
  - 如果后续改用 async，需改用 async_lru 库
  - maxsize=1000 约占用 1000 × 768 维 × 4 bytes ≈ 3MB 内存，可接受

2.5  统一缓存管理器
--------------------------------------------------------------------------------

需要新建的文件：src/cache/__init__.py 和 src/cache/manager.py

    from src.cache.exact_cache import ExactQueryCache
    from src.cache.semantic_cache import SemanticCache

    class CacheManager:
        """统一缓存管理器，协调三层缓存"""

        def __init__(self, embedder=None):
            self.l1 = ExactQueryCache(max_size=200, ttl_seconds=1800)
            self.l2 = SemanticCache(embedder, similarity_threshold=0.92) if embedder else None
            self._hits = 0
            self._misses = 0

        def get(self, query: str, use_rag: bool = True,
                enable_consistency: bool = False) -> dict | None:

            # L1: 精确匹配
            result = self.l1.get(query, use_rag, enable_consistency)
            if result is not None:
                self._hits += 1
                result["cache_level"] = "L1_exact"
                return result

            # L2: 语义匹配（仅当启用 RAG 时，寒暄类不缓存）
            if self.l2 is not None and use_rag:
                result = self.l2.search(query)
                if result is not None:
                    self._hits += 1
                    result["cache_level"] = "L2_semantic"
                    return result

            self._misses += 1
            return None

        def set(self, query: str, result: dict, use_rag: bool = True,
                enable_consistency: bool = False):
            if result.get("refused"):
                return  # 安全拦截不缓存
            self.l1.set(query, result, use_rag, enable_consistency)
            if self.l2 is not None and use_rag:
                self.l2.add(query, result)

        @property
        def hit_rate(self) -> float:
            total = self._hits + self._misses
            return self._hits / total if total > 0 else 0.0

        @property
        def stats(self) -> dict:
            return {
                "hits": self._hits,
                "misses": self._misses,
                "hit_rate": f"{self.hit_rate:.1%}",
            }

阶段三  服务端会话管理 —— 从 localStorage 到安全可控的 Session  ★新增
================================================================================

【目标】将会话数据从前端 localStorage 迁移到服务端，实现安全的 Session 管理、
        Token 过期机制和跨设备的会话持久化能力。

【预计耗时】2-3 天

【价值】
  - 安全性提升：Token 设有效期，超时自动失效
  - 数据不丢失：换设备/清浏览器后数据仍在（登录后从服务端恢复）
  - 多端同步：同一账号在不同设备上看到相同的会话历史
  - 为后期多用户部署打基础

【现状分析】
  当前的安全问题：
    1. 登录 Token 存在 _active_tokens 字典中（内存），服务重启即丢失
    2. 前端所有数据存在 localStorage（会话、收藏、反馈、个人资料）
       → 换设备/清缓存后数据全部丢失
       → 任何能物理接触浏览器的人都能查看数据
       → XSS 攻击可读取 localStorage（document.cookie 有 HttpOnly，
          但 localStorage 没有）
    3. Token 永不过期（_active_tokens 没有 TTL）
    4. /api/chat 等端点不校验 Token（测试阶段设计，生产不可用）

3.1  最小实现方案：JSON 文件持久化 + TTL

说明：考虑到比赛阶段不需要数据库，使用 JSON 文件作为轻量级持久化方案，
      避免引入 SQLite/Redis 的依赖复杂度。

需要新建的文件：web/backend/session_manager.py

    import json
    import secrets
    import time
    from pathlib import Path
    from typing import Optional
    from dataclasses import dataclass, field, asdict

    @dataclass
    class UserSession:
        username: str
        display_name: str = ""
        avatar: str = ""
        bio: str = ""
        conversations: list = field(default_factory=list)
        favorites: list = field(default_factory=list)
        feedbacks: list = field(default_factory=list)

    class SessionManager:
        """基于 JSON 文件的服务端会话管理器"""

        def __init__(self, data_dir: str = None, token_ttl: int = 86400):
            if data_dir is None:
                data_dir = str(Path(__file__).resolve().parents[2] / "sessions")
            self.data_dir = Path(data_dir)
            self.data_dir.mkdir(parents=True, exist_ok=True)
            self.token_ttl = token_ttl  # Token 有效期（秒），默认 24 小时

            # 内存索引: token → (username, expire_timestamp)
            self._tokens: dict[str, tuple[str, float]] = {}
            # 内存缓存: username → UserSession
            self._sessions: dict[str, UserSession] = {}
            self._load_tokens()

        # ===== Token 管理 =====

        def create_token(self, username: str) -> str:
            """生成新 Token，覆盖旧 Token（单点登录）"""
            # 清除该用户的旧 Token
            old_token = None
            for tk, (un, _) in list(self._tokens.items()):
                if un == username:
                    old_token = tk
                    break
            if old_token:
                del self._tokens[old_token]

            token = secrets.token_urlsafe(32)
            expire = time.time() + self.token_ttl
            self._tokens[token] = (username, expire)
            self._save_tokens()
            return token

        def validate_token(self, token: str) -> Optional[str]:
            """验证 Token，返回 username 或 None"""
            entry = self._tokens.get(token)
            if entry is None:
                return None
            username, expire = entry
            if time.time() > expire:
                del self._tokens[token]
                self._save_tokens()
                return None
            # 续期：每次校验通过后延长有效期
            self._tokens[token] = (username, time.time() + self.token_ttl)
            return username

        def revoke_token(self, token: str):
            self._tokens.pop(token, None)
            self._save_tokens()

        # ===== 用户资料 =====

        def get_profile(self, username: str) -> dict:
            session = self._load_user_session(username)
            return {
                "username": session.username,
                "display_name": session.display_name,
                "avatar": session.avatar,
                "bio": session.bio,
            }

        def update_profile(self, username: str, data: dict):
            session = self._load_user_session(username)
            for key in ("display_name", "avatar", "bio"):
                if key in data:
                    setattr(session, key, data[key])
            self._save_user_session(username, session)

        # ===== 会话管理 =====

        def get_conversations(self, username: str) -> list:
            return self._load_user_session(username).conversations

        def save_conversations(self, username: str, conversations: list):
            session = self._load_user_session(username)
            session.conversations = conversations
            self._save_user_session(username, session)

        # ===== 收藏管理 =====

        def get_favorites(self, username: str) -> list:
            return self._load_user_session(username).favorites

        def save_favorites(self, username: str, favorites: list):
            session = self._load_user_session(username)
            session.favorites = favorites
            self._save_user_session(username, session)

        # ===== 内部方法 =====

        def _user_file(self, username: str) -> Path:
            return self.data_dir / f"{username}.json"

        def _load_user_session(self, username: str) -> UserSession:
            if username in self._sessions:
                return self._sessions[username]

            file = self._user_file(username)
            if file.exists():
                try:
                    data = json.loads(file.read_text(encoding="utf-8"))
                    session = UserSession(**data)
                except Exception:
                    session = UserSession(username=username)
            else:
                session = UserSession(username=username)

            self._sessions[username] = session
            return session

        def _save_user_session(self, username: str, session: UserSession):
            self._sessions[username] = session
            self._user_file(username).write_text(
                json.dumps(asdict(session), ensure_ascii=False, indent=2),
                encoding="utf-8",
            )

        def _tokens_file(self) -> Path:
            return self.data_dir / "_tokens.json"

        def _save_tokens(self):
            self._tokens_file().write_text(
                json.dumps(self._tokens, ensure_ascii=False),
                encoding="utf-8",
            )

        def _load_tokens(self):
            file = self._tokens_file()
            if file.exists():
                try:
                    raw = json.loads(file.read_text(encoding="utf-8"))
                    self._tokens = {k: tuple(v) for k, v in raw.items()}
                except Exception:
                    self._tokens = {}
            # 清除过期 Token
            now = time.time()
            self._tokens = {
                k: v for k, v in self._tokens.items() if v[1] > now
            }

    const SESSION_API = {
        // 保存会话（同时写 localStorage 和服务端）
        async saveConversations(conversations) {
            // 1. 本地存储（立即生效，离线可用）
            localStorage.setItem(
                `lawtrust_conv_${currentUser}`,
                JSON.stringify(conversations)
            );
            // 2. 异步同步到服务端（不阻塞 UI）
            try {
                await fetch('/api/user/conversations', {
                    method: 'POST',
                    headers: {'Content-Type': 'application/json'},
                    body: JSON.stringify({
                        token: authToken,
                        conversations: conversations
                    }),
                });
            } catch (e) {
                console.warn('服务端会话同步失败（将使用本地数据）:', e);
            }
        },

        // 加载会话（优先服务端，降级 localStorage）
        async loadConversations() {
            try {
                const resp = await fetch(
                    `/api/user/conversations?token=${authToken}`
                );
                if (resp.ok) {
                    const data = await resp.json();
                    // 服务端数据回写 localStorage
                    if (data.conversations?.length > 0) {
                        localStorage.setItem(
                            `lawtrust_conv_${currentUser}`,
                            JSON.stringify(data.conversations)
                        );
                        return data.conversations;
                    }
                }
            } catch (e) {
                console.warn('服务端加载失败，降级到本地数据');
            }
            // 降级：从 localStorage 读取
            const raw = localStorage.getItem(`lawtrust_conv_${currentUser}`);
            return raw ? JSON.parse(raw) : [];
        },
    };

                    │    ├── 寒暄/简单 ──→ Qwen-7B (本地GPU)   │
                    │    ├── 中等法律 ──→ Qwen-7B + RAG (本地) │
                    │    └── 复杂法律 ──→ 通义千问 API + RAG   │
                    │                                          │
                    │    ├─ 引用核验 (已有)                     │
                    │    └─ 可信评估 (已有)                     │
                    └──────────────────────────────────────────┘

  说明：为什么选择云端服务器部署而非让用户本地下载模型？
    - 竞赛评委体验：打开浏览器即用，无需下载 14GB 模型 + 配置 GPU
    - 环境一致性：服务器环境可控，不会因用户环境差异导致问题
    - 隐私叙事：法律咨询数据不出服务器，本地模型保障隐私，
               只有复杂问题在用户知情同意下调用云端 API
    - 成本：AutoDL A4000 约 1-2 元/小时，竞赛期间约 300-500 元

  要求：必须 GPU 环境。无 CUDA 时服务启动直接报错（不允许纯 API 降级），
        确保所有回答至少经过本地模型处理。

8.1  LLM 抽象层 —— 让模型可替换
-------------------------------------------------------------------------------

【现状问题】
  当前项目中所有 LLM 调用都直接依赖 QwenModel 类（src/llm/qwen_model.py），
  没有接口/抽象基类，无法替换为 API 模型。需要先建立抽象层再做路由。

【解决方案】
  新建 src/llm/base.py —— LLM 统一抽象基类：

需要新建的文件：src/llm/base.py

    from abc import ABC, abstractmethod
    from typing import Dict, Generator, List, Optional


    class BaseLLM(ABC):
        """LLM 统一接口 —— 所有模型（本地/API）必须实现此接口"""

        @abstractmethod
        def generate(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
        ) -> str:
            """同步生成回答"""
            ...

        @abstractmethod
        def generate_stream(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
        ) -> Generator[str, None, None]:
            """流式生成回答"""
            ...

        @property
        @abstractmethod
        def model_name(self) -> str:
            """返回模型标识，如 'qwen2.5-7b'、'qwen-turbo'"""
            ...

        @property
        def capabilities(self) -> Dict:
            """能力标签：is_local, supports_streaming, max_tokens 等"""
            return {
                "is_local": True,
                "supports_streaming": True,
            }

【改造 QwenModel】
  让已有的 QwenModel 继承 BaseLLM（向后兼容，接口不变）：

            return "qwen2.5-7b"

        # generate() 和 generate_stream() 已有，无需修改
        ...

8.2  API 客户端 —— 接入通义千问
-------------------------------------------------------------------------------

【API 选型说明】
  选择通义千问（qwen-turbo）的理由：
    - 与本地 Qwen 同源（阿里通义系列），系统提示词兼容性好
    - 法律场景有优化（通义千问在法律 NLP 评测中表现优秀）
    - 兼容 OpenAI SDK，代码改造成本低
    - 价格适中：qwen-turbo 约 ¥3/百万 token

需要新建的文件：src/llm/api_client.py

    import os
    from typing import Dict, Generator, List, Optional
    from openai import OpenAI

    from src.llm.base import BaseLLM
    from src.llm.qwen_model import _SYSTEM_PROMPT_LEGAL


    class APIClient(BaseLLM):
        """通义千问 API 客户端（兼容 OpenAI SDK）"""

        def __init__(
            self,
            api_key: str = None,
            model_name: str = "qwen-turbo",
            base_url: str = "https://dashscope.aliyuncs.com/compatible-mode/v1",
        ):
            self._api_key = api_key or os.getenv("DASHSCOPE_API_KEY", "")
            self._model_name = model_name
            self._client = OpenAI(
                api_key=self._api_key,
                base_url=base_url,
            )

        @property
        def model_name(self) -> str:
            return self._model_name

        @property
        def capabilities(self) -> Dict:
            return {
                "is_local": False,
                "supports_streaming": True,
                "max_tokens": 8192,
            }

        def _build_messages(
            self,
            query: str,
            system_prompt: str,
            context_docs: Optional[List[str]],
            history: Optional[List[Dict[str, str]]],
            intent_hint: Optional[str],
        ) -> List[Dict[str, str]]:
            """构建 OpenAI 兼容的 messages 格式"""
            user_content = query
            if context_docs:
                ctx = "\n\n".join(context_docs)
                user_content = f"{ctx}\n\n问题：{query}"
                if intent_hint:
                    user_content += f"\n\n（{intent_hint}）"
            elif intent_hint:
                user_content = f"{intent_hint}\n\n用户问题：{query}"

            messages = [{"role": "system", "content": system_prompt}]
            for msg in (history or [])[-20:]:
                messages.append({"role": msg["role"], "content": msg["content"]})
            messages.append({"role": "user", "content": user_content})
            return messages

        def generate(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
        ) -> str:
            system_prompt = system_prompt or _SYSTEM_PROMPT_LEGAL
            temperature = temperature if temperature is not None else 0.4
            max_tokens = max_new_tokens or 1024

            messages = self._build_messages(
                query, system_prompt, context_docs, history, intent_hint
            )

            response = self._client.chat.completions.create(
                model=self._model_name,
                messages=messages,
                temperature=temperature,
                max_tokens=max_tokens,
            )
            return response.choices[0].message.content or ""

        def generate_stream(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
        ) -> Generator[str, None, None]:
            system_prompt = system_prompt or _SYSTEM_PROMPT_LEGAL
            temperature = temperature if temperature is not None else 0.4
            max_tokens = max_new_tokens or 1024

            messages = self._build_messages(
                query, system_prompt, context_docs, history, intent_hint
            )

            stream = self._client.chat.completions.create(
                model=self._model_name,
                messages=messages,
                temperature=temperature,
                max_tokens=max_tokens,
                stream=True,
            )

            for chunk in stream:
                delta = chunk.choices[0].delta
                if delta.content:
                    yield delta.content

注意：
  - 通义千问 API 需要阿里云 DashScope API Key
  - 获取方式：https://dashscope.console.aliyun.com/ → API-KEY 管理
  - 竞赛期间可使用免费额度（新用户通常有 100 万 token 免费额度）
  - 如果后续想切换 DeepSeek，只需改 base_url 和 api_key

8.3  复杂度评估器 —— 决定该用哪个模型
-------------------------------------------------------------------------------

【设计思路】
  用规则评分（非 LLM 评估）判断问题复杂度。零额外延迟、零成本、可解释。

需要新建的文件：src/llm/complexity_assessor.py

    """问题复杂度评估器 —— 基于规则评分，零额外延迟"""
    import re
    from typing import List, Optional, Dict


    # 法域关键词字典（用于统计问题涉及的法域数量）
    _LEGAL_DOMAINS = {
        "劳动": ["劳动", "劳动合同", "辞退", "开除", "解雇", "裁员", "工伤",
                 "社保", "工资", "欠薪", "加班费", "年假", "产假", "试用期"],
        "合同": ["合同", "违约", "赔偿", "定金", "押金", "解除合同"],
        "婚姻家庭": ["离婚", "抚养", "赡养", "继承", "婚前", "婚后", "财产分割"],
        "侵权": ["侵权", "交通事故", "医疗事故", "人身损害", "名誉权"],
        "消费者": ["消费者", "退款", "欺诈", "三包", "虚假宣传"],
        "刑事": ["犯罪", "刑法", "立案", "刑事", "判刑", "拘留", "逮捕"],
        "房产": ["房产", "购房", "租房", "租赁", "产权", "物业"],
        "公司": ["公司", "股权", "股东", "法人", "注册", "破产"],
    }

    # 推理需求模式
    _REASONING_PATTERNS = [
        (r"为什么|如何判断|是否构成|是否属于|是否合法|是否有效", "法律判断"),
        (r"赔偿.*计算|金额.*多少|补偿.*标准|赔偿.*标准", "赔偿计算"),
        (r"怎么办|如何维权|怎么处理|应该怎么做", "操作指引"),
        (r"有什么区别|哪个更好|如何选择", "比较分析"),
    ]

    # 复杂句法模式
    _COMPLEX_SYNTAX_PATTERNS = [
        (r"\?.*\?", "多问句"),           # 含多个问号
        (r"但是|然而|不过|例外|除非", "转折/例外"),
        (r"如果.*那么|假设|假如", "条件假设"),
    ]


    def assess_complexity(
        query: str,
        history: Optional[List[Dict[str, str]]] = None,
    ) -> Dict:
        """
        评估问题复杂度，返回评分和详细分解。

        返回值示例：
        {
            "score": 7,
            "level": "complex",
            "breakdown": {
                "length": 2,        # 问题长度
                "domains": 2,       # 法域数量
                "syntax": 1,        # 句法复杂度
                "reasoning": 2,     # 推理需求
                "context": 0,       # 上下文深度
            },
            "reasons": ["含多个法域(劳动+合同)", "含赔偿计算"],
        }
        """
        breakdown = {}
        reasons = []
        text = query.strip()

        # ---- 维度1: 问题长度 (0-2) ----
        char_count = len(text)
        if char_count < 15:
            breakdown["length"] = 0
        elif char_count <= 50:
            breakdown["length"] = 1
        else:
            breakdown["length"] = 2
            reasons.append(f"问题较长({char_count}字)")

        # ---- 维度2: 法域数量 (0-2) ----
        hit_domains = set()
        for domain, keywords in _LEGAL_DOMAINS.items():
            for kw in keywords:
                if kw in text:
                    hit_domains.add(domain)
                    break
        domain_count = len(hit_domains)
        if domain_count == 0:
            breakdown["domains"] = 0
        elif domain_count == 1:
            breakdown["domains"] = 1
        elif domain_count <= 3:
            breakdown["domains"] = 1 if domain_count == 2 else 2
            reasons.append(f"涉及{domain_count}个法域({', '.join(sorted(hit_domains))})")
        else:
            breakdown["domains"] = 2
            reasons.append(f"涉及{domain_count}个法域(跨领域复杂问题)")

        # ---- 维度3: 句法复杂度 (0-2) ----
        syntax_score = 0
        for pattern, desc in _COMPLEX_SYNTAX_PATTERNS:
            if re.search(pattern, text):
                syntax_score += 1
                reasons.append(f"句法: {desc}")
        breakdown["syntax"] = min(syntax_score, 2)

        # ---- 维度4: 推理需求 (0-2) ----
        reasoning_score = 0
        for pattern, desc in _REASONING_PATTERNS:
            if re.search(pattern, text):
                reasoning_score += 1
                reasons.append(f"需要{desc}")
        breakdown["reasoning"] = min(reasoning_score, 2)

        # ---- 维度5: 上下文深度 (0-2) ----
        context_score = 0
        if history and len(history) >= 2:
            context_score += 1
            reasons.append("有对话历史")
            # 检查是否有跨轮指代
            last_user = [m.get("content", "") for m in history[-4:]
                         if m.get("role") == "user"]
            if len(last_user) >= 2:
                short_queries = sum(1 for q in last_user if len(q) <= 10)
                if short_queries >= 2:
                    context_score += 1
                    reasons.append("跨轮指代")
        breakdown["context"] = min(context_score, 2)

        # ---- 汇总 ----
        total = sum(breakdown.values())

        if total <= 3:
            level = "simple"
        elif total <= 6:
            level = "medium"
        else:
            level = "complex"

        return {
            "score": total,
            "level": level,
            "breakdown": breakdown,
            "reasons": reasons,
        }


    # 示例：
    # >>> assess_complexity("试用期最长多久？")
    # {"score": 1, "level": "simple", ...}
    #
    # >>> assess_complexity("被公司无故辞退怎么办？")
    # {"score": 4, "level": "medium", ...}
    #
    # >>> assess_complexity("公司以经营困难为由裁员但实际在招聘同岗位，是否构成"
    # ...     "违法解除？我可以主张哪些赔偿？计算标准是什么？")
    # {"score": 8, "level": "complex", ...}

8.4  模型路由器 —— 串联缓存、复杂度评估和模型选择
-------------------------------------------------------------------------------

需要新建的文件：src/llm/model_router.py

    import logging
    from typing import Dict, Generator, List, Optional

    from src.config import Config
    from src.llm.base import BaseLLM
    from src.llm.qwen_model import QwenModel
    from src.llm.api_client import APIClient
    from src.llm.complexity_assessor import assess_complexity

    logger = logging.getLogger(__name__)


    class ModelRouter:
        """
        智能模型路由器

        决策流程：
          1. 意图路由 → 寒暄/通用直接走本地模型
          2. 复杂度评估 → 简单/中等走本地，复杂走 API
          3. 缓存层在外部（CacheManager），路由之前检查
          4. API 失败时自动降级到本地模型
        """

        def __init__(
            self,
            local_model: BaseLLM = None,
            api_client: BaseLLM = None,
            cache_manager=None,  # 阶段二引入
        ):
            # 本地模型（必须）
            self.local_model = local_model or QwenModel()

            # API 客户端（可选，未配置时所有请求走本地）
            self.api_client = api_client
            if Config.API_MODEL_ENABLED and api_client is None:
                self.api_client = APIClient(
                    api_key=Config.API_KEY,
                    model_name=Config.API_MODEL_NAME,
                    base_url=Config.API_BASE_URL,
                )

            # 缓存管理器（阶段二引入后可用）
            self.cache_manager = cache_manager

            # 统计（用于答辩展示）
            self._stats = {
                "total": 0,
                "local": 0,
                "api": 0,
                "api_fallback": 0,
                "cache_hits": 0,
            }

        def route(
            self,
            query: str,
            intent: str = "legal_qa",
            history: Optional[List[Dict[str, str]]] = None,
        ) -> tuple[BaseLLM, str, Dict]:
            """
            路由决策。

            返回: (模型实例, 路由标签, 复杂度评估结果)

            路由标签:
              - "local_greeting"   : 寒暄/通用 → 本地 7B
              - "local_direct"     : 简单法律 → 本地 7B 直答
              - "local_rag"        : 中等问题 → 本地 7B + RAG
              - "api_rag"          : 复杂问题 → API + RAG
              - "api_fallback"     : API 降级 → 本地
            """

            # 非法律意图 → 本地模型
            if intent in ("greeting", "general_non_legal"):
                return self.local_model, "local_greeting", {}

            # 法律问题 → 复杂度评估
            complexity = assess_complexity(query, history)
            level = complexity["level"]

            if level == "simple":
                # 0-3 分：本地直答（不需要 RAG）
                return self.local_model, "local_direct", complexity
            elif level == "medium":
                # 4-6 分：本地 + RAG
                return self.local_model, "local_rag", complexity
            else:
                # 7-10 分：API + RAG
                if self.api_client is not None:
                    return self.api_client, "api_rag", complexity
                else:
                    # API 未配置 → 降级到本地
                    logger.warning("API 未配置，复杂问题降级到本地模型")
                    return self.local_model, "api_fallback", complexity

        def generate(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
            intent: str = "legal_qa",
        ) -> tuple[str, str, Dict]:
            """
            路由 + 生成。

            返回: (回答文本, 路由标签, 复杂度评估结果)
            """
            model, route_tag, complexity = self.route(query, intent, history)
            self._stats["total"] += 1

            if route_tag.startswith("api"):
                self._stats["api"] += 1
                try:
                    result = model.generate(
                        query,
                        system_prompt=system_prompt,
                        temperature=temperature,
                        max_new_tokens=max_new_tokens,
                        context_docs=context_docs,
                        history=history,
                        intent_hint=intent_hint,
                    )
                    return result, route_tag, complexity
                except Exception as e:
                    logger.warning(f"API 调用失败: {e}，降级到本地模型")
                    self._stats["api_fallback"] += 1
                    route_tag = "api_fallback"
                    model = self.local_model
            else:
                self._stats["local"] += 1

            result = model.generate(
                query,
                system_prompt=system_prompt,
                temperature=temperature,
                max_new_tokens=max_new_tokens,
                context_docs=context_docs,
                history=history,
                intent_hint=intent_hint,
            )
            return result, route_tag, complexity

        def generate_stream(
            self,
            query: str,
            system_prompt: str = None,
            temperature: float = None,
            max_new_tokens: int = None,
            context_docs: List[str] = None,
            history: Optional[List[Dict[str, str]]] = None,
            intent_hint: Optional[str] = None,
            intent: str = "legal_qa",
        ) -> Generator[str, None, None]:
            """流式路由 + 生成（API 失败时无法降级流式，改为同步重试）"""
            model, route_tag, complexity = self.route(query, intent, history)
            self._stats["total"] += 1

            if route_tag.startswith("api"):
                self._stats["api"] += 1
                try:
                    yield from model.generate_stream(
                        query,
                        system_prompt=system_prompt,
                        temperature=temperature,
                        max_new_tokens=max_new_tokens,
                        context_docs=context_docs,
                        history=history,
                        intent_hint=intent_hint,
                    )
                    return
                except Exception as e:
                    logger.warning(f"API 流式调用失败: {e}")
                    self._stats["api_fallback"] += 1
                    model = self.local_model
            else:
                self._stats["local"] += 1

            yield from model.generate_stream(
                query,
                system_prompt=system_prompt,
                temperature=temperature,
                max_new_tokens=max_new_tokens,
                context_docs=context_docs,
                history=history,
                intent_hint=intent_hint,
            )

        @property
        def stats(self) -> Dict:
            return {
                **_stats,
                "local_pct": f"{_stats['local']/max(_stats['total'],1):.0%}",
                "api_pct": f"{_stats['api']/max(_stats['total'],1):.0%}",
            }


    # 使用示例：
    #
    # router = ModelRouter()
    #
    # # 简单问题 → 路由到本地
    # answer, tag, cx = router.generate("试用期最长多久？", intent="legal_qa")
    # print(tag)  # "local_direct"
    #
    # # 复杂问题 → 路由到 API
    # answer, tag, cx = router.generate(
    #     "公司以经营困难裁员但实际在招同岗位，是否构成违法解除？赔偿怎么算？",
    #     intent="legal_qa"
    # )
    # print(tag)  # "api_rag"

8.9  验收标准
-------------------------------------------------------------------------------

  □ 简单问题（如"试用期最长多久？"）走本地模型，route_tag = "local_direct"
  □ 中等问题（如"被公司无故辞退怎么办？"）走本地+RAG，route_tag = "local_rag"
  □ 复杂问题（如含赔偿计算+违法解除的多问句）走 API+RAG，route_tag = "api_rag"
  □ API 不可用时（如 API Key 无效），自动降级到本地模型，route_tag = "api_fallback"
  □ 前端显示模型来源标签（本地/云端/降级）
  □ 访问 /api/debug/router-stats 有正确的统计数据
  □ 非法律意图（寒暄/通用）不受复杂度路由影响，始终走本地模型
  □ 安全拦截问题不经过模型路由（在 input_guard 层已拦截）

--------------------------------------------------------------------------------
A.1  三种部署方案对比
--------------------------------------------------------------------------------

方案A：云端服务器部署（本竞赛推荐）
──────────────────────────────────

  架构：
    用户浏览器 ──→ 云服务器(AutoDL) ──→ Qwen-7B(本地GPU，简单问题)
                                    ──→ 通义千问API(复杂问题)

  优点：
    ✅ 用户零配置，打开浏览器即用（竞赛评委体验最佳）
    ✅ 环境完全可控，不会因用户环境差异导致问题
    ✅ 模型统一管理，换版本只需在服务器操作一次
    ✅ 可以构建"数据不出服务器"的隐私叙事

  缺点：
    ❌ 需要 GPU 云服务器（AutoDL A4000 约 1-2 元/小时）
    ❌ 服务器需要稳定的网络环境
    ❌ 多人同时使用时 GPU 显存可能不足（Qwen-7B fp16 约 14GB）

  适用场景：
    竞赛答辩演示、团队内部测试、项目展示


方案B：用户本地部署模型
──────────────────────

  架构：
    用户电脑 ──→ 本地 Qwen-7B(GPU) ──→ 仅本地推理

  优点：
    ✅ 服务器零成本
    ✅ 数据完全不出本机（最强隐私保护）

  缺点：
    ❌ 用户需要 GPU（至少 16GB 显存）
    ❌ 用户需要下载 14GB 模型文件
    ❌ 环境配置复杂（CUDA、cuDNN、PyTorch 版本兼容）
    ❌ 无法控制用户端的模型版本
    ❌ 对竞赛评委极不友好

  适用场景：
    个人长期使用、数据高度敏感场景、非竞赛环境


方案C：纯 API 方案
─────────────────

  架构：
    用户浏览器 ──→ 轻量服务器 ──→ 通义千问/DeepSeek API

  优点：
    ✅ 零部署复杂度，最轻量
    ✅ 不需要 GPU 服务器
    ✅ 模型能力最强（API 大模型通常优于 7B 本地模型）

  缺点：
    ❌ 所有请求都产生 API 费用
    ❌ 依赖外部服务可用性
    ❌ 用户数据发送到第三方（隐私顾虑）

  适用场景：
    快速原型验证、无 GPU 环境、预算充足


--------------------------------------------------------------------------------
A.2  本次竞赛选择：方案A（云端服务器部署）
--------------------------------------------------------------------------------

决策依据：
  1. 评委体验优先：打开浏览器即用是最低摩擦的体验
  2. 成本可控：竞赛期间（1-2 个月）GPU 租赁约 300-500 元，API 免费额度够用
  3. 隐私叙事：91% 请求由本地模型在服务器端处理，仅有 8% 复杂问题调用 API
     且用户在界面上可见「云端大模型」标签，透明可控
  4. 可展示性强：答辩时可以演示路由架构图、命中率统计、成本对比

硬件要求：
  - GPU：至少 16GB 显存（推荐 RTX A4000 / RTX 3080 / RTX 4070）
  - 内存：至少 16GB
  - 磁盘：至少 50GB（模型 14GB + 向量库 + 数据）
  - 网络：稳定的公网连接（用于 API 调用和内网穿透）

强制要求：
  - 必须有 GPU 环境。无 CUDA 时服务启动直接报错退出，不允许纯 API 降级。
  - 这是为了确保所有回答至少经过本地模型处理，简单问题不消耗 API 额度。

推荐云平台：
  - AutoDL（https://www.autodl.com/）：按量计费，A4000 约 0.88 元/小时
  - 阿里云 GPU 云服务器：ecs.gn6i-c8g1.2xlarge（T4 16GB）
  - 矩池云（https://www.matpool.com/）：学生优惠

A.3  API 配置说明（通义千问）

  3. 创建新的 API Key 并复制
  4. 设置环境变量：export DASHSCOPE_API_KEY="your-key"
  5. 或在 src/config.py 的 API_KEY 中直接填写

可用模型：
  模型              价格（输入/输出，每百万token）    说明
  ─────────────────────────────────────────────────────────

  qwen-max           ¥20 / ¥60                     最强，复杂法律推理
  qwen-turbo-latest  ¥2 / ¥4                       最新版本

隐私说明：

  - 仅在用户问题被判定为"复杂法律推理"时触发 API 调用

B.4  常见问题
--------------------------------------------------------------------------------

  Q: 页面打不开，显示"无法连接"？
  A: 可能是服务端电脑关机或内网穿透断开了。
     请联系服务端管理员确认服务是否正在运行。

  Q: 回答很慢？
  A: 法律类问题需要检索法条 + 大模型推理，通常需要 15-60 秒。
     如果超过 2 分钟无响应，请刷新页面重试。

  Q: 回答内容不准确？
  A: 点击右侧"引用核验"Tab 可以查看法条引用是否准确。
     如果发现错误，可以用 👍👎 反馈。

  Q: 支持哪些文件格式上传？
  A: 支持 txt、md、docx、pdf、jpg/png/bmp 等。
     单文件不超过 10MB，最多 5 个附件。

  Q: 我换了浏览器，之前的会话还在吗？
  A: 同一账号登录后，会话和收藏会自动从服务端同步恢复。

  第1周：阶段〇（基础修复） + 阶段一（流式输出加固）

  第2周：阶段二（问答缓存层） + 阶段三（服务端会话管理）
     → 性能和安全双提升，这是与同类项目拉开差距的关键

  第3周：阶段七（数据工程）
     → 扩展法律数据，构建评测数据集

  第4周：阶段四（效果对比框架）
     → 跑出对比数据，形成量化报告

  第5周：阶段五（LangSmith） + 阶段六（多用户并发）
     → 工程化完善

  第6周：阶段九（一键部署与团队测试）
     → 让团队成员开始测试，收集反馈

  第7周：阶段八（架构升级）的核心部分
     → 实现 LLM 抽象层 + 通义千问 API 客户端 + 复杂度评估器 + 模型路由器
     → 这是答辩中最出彩的架构亮点，建议优先保障
     → 多智能体和知识图谱根据剩余时间选做

  第8周：整合、调试、录制演示视频、准备答辩材料

    - 一键部署（阶段九）让项目具备"可复现性"，是学术竞赛的评审加分项
    - 不要追求全部做完——哪怕只做到阶段四，只要数据扎实、演示流畅，
      也比全做但每样都半成品好得多
