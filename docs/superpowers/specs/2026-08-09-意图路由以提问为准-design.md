# 意图路由修复：文档分析以提问为准

日期：2026-08-09
状态：已确认（用户审阅前）

## 背景与问题

用户上传与法律无关的 TXT 文档（如《修改日志.txt》）并提问「文档内容说了什么」，模型仍按【结论】【法律分析】【依据法条】三段式作答，并生成评估详情。用户期望：**非法律问题按路由简单回答并提示用户**，不套法律格式、不生成评估详情。

## 根因分析

三层叠加导致：

1. **意图路由强制分类**：[intent_router.py](src/pipeline/intent_router.py) 中 `classify_intent` 规定「只要上传了文档就强制按 legal_qa 处理」（`has_documents=True → IntentResult("legal_qa", 0.85)`）。该逻辑是此前修复「模型读不到文档」时加的保险。
2. **文档涉法判定误判**：[answer_pipeline.py](src/pipeline/answer_pipeline.py) 的 `_is_document_analysis` 用关键词表扫描文档全文——《修改日志.txt》记录了项目对法律功能的开发，出现「法条」「劳动合同」等词即被判为涉法 → 走完整法律流程：RAG 检索《民法典》《劳动合同法》参考法条注入（回答中「与用户提供的《民法典》及《劳动合同法》参考法条无直接关联」即由此而来）、强制三段式法律提示词。
3. **评估详情跟随 intent**：前端 [answer.ts](web/frontend/src/utils/answer.ts) 的 `isLegalAnalysisMeta` 对任何非 greeting/general_non_legal 的 intent 返回 true → intent 为 legal_qa 时详情面板必然生成。

核心结论：**判定依据错了**。应按提问（query）判定是否为法律问题，文档只是内容素材。

## 目标

- 非法律文档 + 无法律词提问 → 非法律路由：客观总结 + 提示用户，不套三段式、不罗列法条、不生成评估详情。
- 不破坏既有正确行为：法律提问（含涉法文档场景）行为不变。
- 全面检查各类型提问的路由符合预期。

## 设计

### 一、新意图路由规则（classify_intent）

判定只看提问内容，优先级顺序：

| 优先级 | 条件 | 路由结果 |
|---|---|---|
| 1 | 空输入 | general_non_legal（1.0，「空输入」） |
| 2 | 寒暄（你好/谢谢/再见…） | greeting（0.95） |
| 3 | 提问含法律关键词 | legal_qa（0.92，不变） |
| 4 | 提问含非法律信号词（天气/翻译/编程…） | general_non_legal（0.88，不变） |
| 5 | 提问无法律词 + 携带用户文档 | general_non_legal（0.85，「非法律文档分析请求」） |
| 6 | 历史对话含法律上下文 | legal_qa（0.75，仅无文档时命中——文档分析优先于历史延续） |
| 7 | 短输入（≤8 字） | greeting（0.7） |
| 8 | 兜底 | general_non_legal（0.65） |

签名变化：`classify_intent(query, history=None, user_documents=None)`，以 `bool(user_documents)` 取代原 `has_documents` 参数。

关键语义：**是不是法律问题由「问什么」决定**。「文档内容说了什么」→ 命中第 5 条 → 非法律。`has_legal_keywords` 公开包装保留（供其他调用方），不再用于文档文本扫描。

### 二、文档分析模式的行为（后端）

- 路由为 general_non_legal → 走后端既有非法律分支（main.py chat_stream 中 `ctx.intent.intent in ("greeting", "general_non_legal")`）：不计算可信分、不启动引用核验，`done` 事件带 `non_legal=True` 与 intent → 前端 `isLegalAnalysisMeta` 返回 false → 自动不生成评估详情、不显示详情面板。**前端零改动**。
- 修复隐藏问题：非法律分支当前 `context_docs=None`（文档被丢弃，是此前「模型读不到文档」的根源结构）→ 改为：携带文档时将用户文档文本构建为 `context_docs` 注入，模型才能总结文档。
- 提示词：general_non_legal + 携带文档 → 用文档分析专用 prompt（`_SYSTEM_PROMPT_DOC_ANALYSIS`，补一句结尾引导：「如需法律咨询可提出具体问题或上传合同等法律文件」）；不带文档 → 原通用 prompt。
- 跳过 RAG：非法律分支本就不检索 → 不再出现「罗列无关法条」。
- 涉法文档 + 无法律词提问（如合同 + 「帮我看看这个文档」）：模型按 prompt 自判文档涉法 → 仍按三段式基于文档条款分析（prompt 已支持），但不自动检索法条、不生成评估详情。

### 三、文件改动清单

| 文件 | 改动 |
|---|---|
| src/pipeline/intent_router.py | `classify_intent` 签名 `has_documents: bool` → `user_documents: Optional[List[Dict]]`；按第一节新顺序重排；删除「携带文档强制 legal_qa」；文档文本不再参与关键词扫描；`has_legal_keywords` 公开包装保留 |
| src/pipeline/answer_pipeline.py | `run` / `prepare_context` 调用 `classify_intent` 时传 `user_documents`；**general_non_legal 分支**（`_run_non_legal` + `prepare_context` 的 general 分支）注入文档 context_docs（`format_user_documents`）且携带文档时 system_prompt 用 `get_system_prompt("general_non_legal", document_mode=True)`；**greeting 分支保持原样**（寒暄回复不需要文档，不注入、不用 document_mode）；`generate_answer_stream` 非法律分支 `context_docs=None` → `ctx.context_docs`；删除 `_is_document_analysis` 静态方法（判定并入路由） |
| src/llm/qwen_model.py | `get_system_prompt` 中 `document_mode=True` 判定前置（先于 intent 分支，greeting 不受影响）；`_SYSTEM_PROMPT_DOC_ANALYSIS` 补结尾提示句 |
| 前端 | 零改动 |

### 四、行为回退（有意为之）

合同文档 + 无法律词提问（如「帮我看看这个文档」）：不再自动 RAG 检索法条，模型凭自身知识 + 文档条款分析，末尾提示可提出具体问题获取法条引用。这是「以提问为准」的必然代价，其余场景全部保持或改善。
