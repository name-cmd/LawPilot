一、环境准备与访问入口
================================================================================

【启动服务】
  在项目根目录执行：
    pip install -r requirements.txt
    copy .env.example .env            # 填写 DASHSCOPE_API_KEY（参考项目介绍文档）
    python scripts/convert_md_to_json.py          # 首次需数据准备
    python scripts/build_knowledge_base.py        # 首次需构建向量库
    python scripts/run_server.py
  或直接双击根目录 start_server.bat（自动检查依赖/知识库/API Key/端口占用）。

【访问地址】
  · 浏览器打开：http://localhost:6006（根路径自动跳转 /ui/index.html）
  · API 文档（Swagger）：http://localhost:6006/docs
  · 健康检查：GET /api/health → {"status": "ok"}
  · 注意：前端改动后需重新 npm run build 并 Ctrl+F5 硬刷新（避免缓存旧入口）

【系统要求】
  · API 模式无需 GPU（仅 bge/NLI 小模型，CPU 可跑）；本地离线引擎需 CUDA GPU
    + models/ 权重（Web 端离线调用暂缓，未就绪自动置灰）

二、登录、注册与协议
================================================================================

【功能 01】用户登录
  说明：进入系统前须登录；未登录访问任何页面都会跳回登录页。
  操作：输入用户名 + 密码 → 点击「登录」（可勾选「记住密码」）
  测试：
    T01 正确账号：root / 123456 → 进入协议确认弹窗（未勾选协议时「同意并
        继续」按钮不可用；勾选后可进入主界面）
    T02 错误密码：root / 123456 改成错误密码 → 红色错误提示，不进入系统
    T03 记住密码：勾选后刷新页面账号密码自动回填；取消勾选登录则清除记录

【功能 02】注册新账号
  说明：测试阶段开放注册，用户名 + 密码即可创建账号，注册成功自动登录。
  操作：登录页底部「立即注册」→ 输入用户名/密码 → 提交
  测试：
    T04 正常注册：用户名 lawuser01、密码 123456 → 注册成功并直接进入主界面
    T05 用户名重名：再注册 lawuser01 → 提示「用户名已被注册」
    T06 非法用户名：123（数字开头）/ abc（不足 3 位）→ 校验提示
    T07 密码过短：12345（5 位）→ 提示「密码至少 6 位」

【功能 03】法律协议确认
  说明：登录成功后弹出「欢迎使用律策智枢 LawPilot」协议框，须勾选同意后方可进入。
  协议：《用户协议》《隐私政策》《AI 咨询非正式法律意见声明》（可点击查看全文）
  测试：
    T08 不勾选直接点「同意并继续」→ 按钮禁用不可点击
    T09 勾选后进入 → 显示三栏主界面

【功能 04】登录态保持与退出
  说明：Token 保存在 localStorage，刷新页面自动校验登录态；Token 24 小时
        滑动续期。
  操作：右上角账号菜单（头像+用户名胶囊按钮）→「退出登录」
  测试：
    T10 登录后刷新页面 → 保持登录状态直接进入主界面
    T11 退出登录 → 回到登录页；再登录 → 会话/收藏/资料自动恢复

四、模型选择与问答选项
================================================================================

【功能 07】模型选择器
  说明：输入区右下角模型选择器，两级选择：
    · 离线调用：本地 Qwen2.5-7B（需 GPU+权重；未就绪自动置灰，悬停显示原因）
    · API 调用：Auto（跟随设置面板全局默认模型，默认 qwen3.7-plus）或
      7 款具体模型：qwen3.7-plus / qwen-turbo / qwen3.7-max /
      deepseek-v4-flash-0731 / deepseek-v4-pro / kimi-k2.6 / glm-5.2
  展示：选择器摘要按钮显示品牌 logo（Auto 显示星光渐变标识）；回答气泡
        左下角显示模型角标（含品牌 logo，Auto 显示星光 + 悬停可见实际模型名）
  测试：
    T15 打开选择器 → 7 款模型 + Auto + 离线调用齐全，均带品牌 logo
    T16 切换为 glm-5.2 后提问 → 回答角标显示 GLM logo 与模型名
    T17 选 Auto 提问 → 角标显示星光「Auto」，悬停显示实际使用模型
    T18 选择「离线调用」→ 提示离线引擎暂缓/未就绪原因，无法发送

【功能 08】问答选项开关
  说明：输入区底部两个开关 + 设置面板中可调项：
    · RAG 法条检索（默认开启）：是否从向量库检索并注入法条
    · 自一致性评估（默认关闭，较慢）：多次采样评估鲁棒性
    · NLI 引用核验（默认开启）：隐性论断支撑判断（设置面板「检索与引用」区）
    · 自一致性采样次数：2 / 3 / 5 次（设置面板「检索与引用」区）
    · 引用展示风格：简洁 / 完整（设置面板「检索与引用」区）
  测试：
    T19 关闭 RAG 提问「劳动合同解除需要提前多少天通知？」→ 回答无法条溯源，
        可信分通常低于开启 RAG 时（对比测试，见 T50）
    T20 开启自一致性评估提问 → 回答耗时明显增加，可信评估中鲁棒性显示
        多次采样一致度数据

五、设置面板（六个分区）
================================================================================

【功能 09】设置面板
  入口：账号菜单 →「设置」（齿轮），左侧导航 + 右侧内容布局
  分区与功能：
    · 通用：外观（浅色 / 深色 / 跟随系统）、字体大小（标准 / 偏大 / 超大）、
      界面语言（当前仅简体中文）
    · 模型与推理：全局默认模型（Auto 跟随项，默认 qwen3.7-plus）；自配百炼
      API Key 输入框（形如 sk-*******；未配置时该账号回退服务端 .env Key，
      root 默认）；深度思考模式（适合复杂法律推理，响应更慢）
    · 检索与引用：RAG 法条检索 / 引用核验（NLI）开关、自一致性采样次数
      （2/3/5）、引用展示风格（简洁 / 完整）
    · 可信评估：启用六维可信评估开关 + 六个评估维度勾选（事实准确性 / 法律
      依据 / 逻辑一致性 / 时效性 / 完整性 / 安全性）
    · 隐私与安全：敏感信息主动提示开关（输入守卫发现身份证号、手机号等隐私
      内容时提醒）；修改密码（需旧密码校验，成功后吊销其他设备 Token）
    · 数据管理：导出会话与收藏（下载 JSON 备份到本地）；清空全部个人数据
      （二次确认，清会话/收藏/资料，保留账号与自配 API Key）
  测试：
    T21 检索与引用：关闭 NLI 后提问 → 引用核验面板不再显示隐性论断判断（或
        显示未评估）；恢复开启
    T22 自配 API Key：输入无效 Key（如 sk-0000）保存后提问 → 报中文错误提示
        （API 鉴权失败类文案）；改回空值保存 → 恢复服务端默认 Key 正常问答
    T23 修改密码：旧密码错误 → 400 提示；新密码过短 → 提示；成功后其他设备
        Token 被吊销（当前设备保持登录），旧密码登录失败、新密码可登录
    T24 清空全部个人数据 → 二次确认后会话/收藏清空，账号与 API Key 保留
        （顶栏清空对话记录仅清会话不清收藏，可对照测试）
    T24a 可信评估：关闭某个维度（如安全性）→ 可信评估面板雷达图不再显示该
        维度；恢复勾选后重新显示
    T24b 导出数据：点击导出 → 浏览器下载 lawtrust-backup-*.json，内容包含
        会话与收藏；导入需手动（当前仅导出）

七、法律咨询问答（核心功能）
================================================================================

【功能 15】问答输入区
  说明：多行输入框；Enter 发送、Shift+Enter 换行；发送后按钮显示「分析中…」；
        输入区旁有「📎 上传文档」按钮（见第八章）。
  测试：
    T32 输入问题按 Enter 发送 → 消息上屏，按钮进入加载状态，流式输出开始

【功能 16】结构化法律回答
  说明：法律类回复按固定三段式展示：
    · 【结论】— 简明结论
    · 【法律分析】— 结合事实与法条的推理
    · 【依据法条】— 引用条文（法律名称品牌蓝加粗斜体、条号品牌蓝加粗高亮）
  测试：
    T33 提问「离婚冷静期是多长时间？」→ 回答含三段式，依据法条为《民法典》
        第一千零七十七条，条号/法名高亮显示

【功能 17】流式问答（SSE）
  说明：法律类问题默认走 /api/chat/stream，逐字输出（打字机效果）；流程为
        meta（模型名/任务类型/意图）→ 智能体状态事件（如触发）→ 逐 token →
        done（可信分等）；流式失败自动降级同步接口。
  测试：
    T34 任意法律问题 → 回答逐字显示；完成后消息左下角出现模型角标

【功能 18】智能体状态行与任务类型
  说明：AI 回答上方按任务类型展示：
    · 工具调用触发时：状态行「● 正在检索法条…」→「✓ 命中 N 条法条」（done 后消失）
    · 时效查询（validity_check）：回答标注「◈ 来源：法律时效注册表」
    · 合同审查（contract_review）：输出【合同风险清单】+【总体评价】
  测试（建议切换模型 glm-5.2 触发工具调用）：
    T35 提问「工伤认定申请时效和劳动仲裁时效分别是多少？」→ 回答过程出现
        工具状态行（正在检索法条→命中 N 条），回答为三段式，详情面板出现
        「工具轨迹」Tab（见功能 27）
    T36 提问「婚姻法现在还有效吗？」→ 直查时效注册表给出确定性结论（已废止、
        参见民法典），标注「◈ 来源：法律时效注册表」，不套三段式
    T37 提问「收养法还有效吗？」/「专利法还有效吗？」→ 同样走时效查询
        （注册表驱动，不硬编码法律名单）
    T38 普通问题「你好」→ 无工具状态行、无时效标注

【功能 19】异步引用核验（WebSocket）
  说明：流式首版回答完成后，引用核验与完整六维评分在后台异步执行，经
        WebSocket 推送结果动态更新；核验期间气泡显示「引用核验中…」。
  测试：
    T39 提问「用人单位拖欠工资，适用《劳动合同法》第一条吗？」→ 回答完成后
        数秒内「引用核验中…」消失，右侧引用核验 Tab 出现完整对照结果
    T40 核验期间切换到其他会话再切回 → 核验结果仍正常显示（跨会话不丢结果）

【功能 20】多轮对话
  测试：
    T41 先问「试用期最长多久？」，再追问「试用期工资有规定吗？」→ 追问带
        上下文，回答连贯

八、文档上传与辅助分析
================================================================================

【功能 21】上传文档
  说明：点击「📎 上传文档」选择文件，附件显示在输入区下方（解析中/字数/
        移除按钮，最多 5 个）。
  支持格式：txt、md、docx、pdf、jpg/png/bmp/tiff/webp（图片走 OCR）
  限制：最多 5 个附件，单文件 10MB，注入上下文最多 12000 字符
  测试数据：docs/测试文件/ 目录下已备好：
    · 合同案例1.txt — 软件开发服务合同（含付款节点/知识产权/违约金/赔偿限额条款）
    · 合同案例2.txt — 劳动合同（含试用期工资/月薪/离职违约金条款）
    · 借条.txt — 个人借贷借条（金额/利率/逾期利息/违约金）
    · 借条图片.png — 借条图片（OCR 识别测试）
    · 技术说明文档.txt — 非法律技术文档（文档分析模式测试）

【功能 22】合同审查（contract_review）
  说明：上传合同类文档 + 含审查信号的提问 → 任务类型 contract_review，
        回答结构化为【合同风险清单】（逐条风险 + 依据）+【总体评价】；
        回答中引用文档原文处经「文档引文核验」逐字比对（防止编造条款）。
  测试：
    T42 上传 docs/测试文件/合同案例1.txt，提问「这份合同有什么风险条款？」
        → 回答含【合同风险清单】【总体评价】；详情面板引用核验 Tab 出现
        「文档引文核验」区块，引用原文标注「与上传文档原文一致」
    T43 上传 docs/测试文件/合同案例2.txt（劳动合同），提问「这份合同有哪些
        不合规的地方？」→ 针对试用期工资、违约金条款给出劳动法依据
    T44 不上传文档直接提问「帮我审一下这份合同」→ 引导文案提示先上传合同
        文件（如「请上传合同文件后再提问」），不浪费模型调用

【功能 23】纯文档提问
  说明：仅上传文档不输入文字 → 自动以「请分析以上上传的文档内容…」提问。
  测试：
    T45 上传 借条.txt 不输入文字直接发送 → 自动提问并分析借条要点

【功能 24】图片 OCR 识别

十七、常见问题
================================================================================

Q1：页面打不开或一直加载？
A1：确认已执行 python scripts/run_server.py 且访问 http://localhost:6006
    （不是 8000）；检查 /api/health 是否返回 ok；前端改动后需重新
    npm run build 并 Ctrl+F5 硬刷新。

Q2：回答很慢或报错？
A2：API 模式检查 .env 的 DASHSCOPE_API_KEY 是否正确、是否还有免费额度；
    首次提问需加载 bge/NLI 小模型较慢属正常；勾选自一致性评估会明显变慢。

Q3：可信分角标/详情迟迟不刷新？
A3：流式模式下引用核验异步执行，需等 WebSocket 推送（通常数秒至数十秒）；
    期间气泡显示「引用核验中…」。若长期不更新，点击该消息触发自愈重连。

Q4：上传文档失败或模型不引用文档内容？
A4：检查格式（txt/md/docx/pdf/图片）与大小（≤10MB，最多 5 个）；图片需
    OCR 依赖（rapidocr）；提问须与文档相关（纯文档上传会自动生成分析提问）。

Q5：为什么合同审查不生效？
A5：合同审查需要「携带文档 + 审查信号」（如「这份合同有什么风险」）；仅
    上传文档但提问不含审查/法律意图时按文档分析处理；无文档直接问审查
    会收到引导上传文案。

Q6：为什么工具轨迹 Tab 不出现？
A6：工具调用由模型自主决策：部分模型（如默认 qwen3.7-plus）对单轮简单
    法律问题可能不触发工具调用，属正常行为；演示工具调用建议切换
    glm-5.2 并提问多法条对比类问题（如 T35/T67）。

Q7：切换账号后看到上一账号的历史？
A7：已修复的已知 bug——账号数据按用户名隔离（服务端 data/users/ +
    本地 localStorage 均按用户隔离）；若仍复现，请确认前端已重新构建部署
    （npm run build）且浏览器硬刷新。

Q8：会话/收藏数据丢失？
A8：正常登录状态下数据存服务端（data/users/），换设备/清缓存后重新登录
    会自动恢复；仅当服务端数据目录被删除或未登录使用（guest 数据仅存本地）
    才会丢失。
