================================================================================
一、项目概述
================================================================================

法信通（LawTrust）是一个面向中文法律场景的可信智能问答与多维可信评估平台。
项目以「法条级事实可追溯」为核心目标，将大语言模型（本地 Qwen2.5-7B-Instruct
或阿里云百炼 qwen3.7-plus API，双模式可切换）、检索增强生成（RAG）、三级引用
核验、TrustLLM 六维可信框架本地化评估、用户文档解析（合同/文书）以及输入安全
守卫等能力整合为统一流水线，并通过 FastAPI 后端与单页 Web 前端提供可交互的
演示环境。

与通用聊天机器人不同，法信通在法律咨询路径上强制要求结构化作答（结论、法律
分析、依据法条），并在生成后对引用准确性进行自动核验；若核验未通过，系统会
触发一次自动修正重生成。同时，平台借鉴 TrustLLM 论文的六维评估思路，在本地
以规则引擎、引用核验结果和可选自一致性采样对每次法律回答进行可信度打分与
证据说明，无需调用付费 GPT 评测 API。

Web 端现已支持用户登录、个人资料管理、会话与收藏本地持久化、文档上传辅助
分析、流式问答与 WebSocket 异步核验、可信评估报告导出等完整交互能力。

二、技术栈
================================================================================

【基础模型】
  - 大语言模型：双模式——① 本地 Qwen2.5-7B-Instruct（HuggingFace Transformers 推理，需 GPU）；
    ② 阿里云百炼 qwen3.7-plus API（OpenAI 兼容接口，默认，无需 GPU，新模型赠送 100 万 token 免费额度）。
    由 src/config.py 的 LLM_PROVIDER 开关切换（"api" / "local"）
  - 嵌入模型：bge-base-zh-v1.5（中文法律条文语义检索，本地，CPU 可跑）
  - NLI 模型：Erlangshen-Roberta-330M-NLI（隐性法律论断支撑判断，可选，本地，CPU 可跑）

【检索与存储】
  - 向量数据库：ChromaDB（持久化目录 law_db/）
  - 检索框架：LangChain Community（Chroma 向量存储封装）
  - 法律数据：6 部现行法律 Markdown 源文件 + 废止法律注册表（law_registry.json）
  - 法律时效：law_repeals.json 记录婚姻法、合同法等废止关系

【后端服务】
  - Web 框架：FastAPI + Uvicorn（默认端口 6006）
  - 流式传输：SSE（/api/chat/stream）+ WebSocket（/ws/verification/{message_id}）
  - 数据校验：Pydantic v2
  - 运行环境：Python 3.x；API 模式无需 GPU（仅 bge/NLI 小模型，CPU 可跑）；本地模式推荐 CUDA GPU

【前端演示】
  - 单页应用：原生 HTML + CSS + JavaScript（无构建步骤）
  - 图表可视化：ECharts 5（六维可信雷达图）
  - 本地存储：localStorage（登录态、会话、收藏、个人资料，按用户隔离）

【文档处理】
  - 支持格式：txt、md、docx、pdf、jpg/png 等图片（OCR）
  - OCR 引擎：rapidocr（可配置 paddleocr）
  - 单文件上限 10MB，最多 5 个附件，注入上下文最多 12000 字符

【评测与工具】
  - 单元测试：pytest
  - 离线基准：LegalTrustBench + run_legal_trust_benchmark.py
  - 命令行 Demo：scripts/demo.py

四、主要模块说明
================================================================================

【AnswerPipeline 问答流水线】是整个系统的调度中枢。用户问题首先经过意图路由器
判断属于法律咨询、寒暄问候还是通用非法律问题。对于寒暄和通用非法律类输入，
系统切换至专用 system prompt，不注入 RAG 检索结果，也不执行引用核验与六维
可信评分，Web 端同步隐藏可信评估、法条溯源与引用核验详情面板。对于法律咨询类
输入，查询重写模块会先剥离身份证号、手机号等噪声词，并根据「辞退」「欠薪」等
关键词扩展检索查询；随后进行多路向量检索，仅保留相关度高于阈值（默认 0.35）
的法条注入模型上下文。若用户上传了合同/文书，文档解析结果与 RAG 法条合并
注入上下文。模型按【结论】【法律分析】【依据法条】结构生成回答后，
CitationVerifier 对显式引用做存在性、内容吻合度及隐性论断三级核验；若引用
分数低于阈值且存在可修正引用，则自动重生成一次。若检测到用户问「辞退」而回答
仅围绕「扣押身份证」偏题，还会触发一次聚焦核心诉求的重生成。最后 LegalTrustScorer
计算六维可信分并返回完整元数据。

流式模式下，系统先通过 SSE 快速输出首版回答与初步可信分，随后在后台异步
执行完整引用核验与六维评分，结果经 WebSocket 推送给前端动态更新。

【InputGuard 输入守卫】在 Web 提交与 API 层双重生效。对伪造证据、逃避法律
责任、洗钱等滥用模式直接拒答，不调用大模型；对身份证号、银行卡号等极度敏感
信息自动脱敏；对手机号、详细地址等一般隐私信息弹出确认框，用户确认后才继续
发送。拒答以「安全拦截」样式展示，不参与可信评估。

【LegalTrustScorer 六维可信评分】是 TrustLLM 框架的本地化实现。真实性维度综合
引用核验准确率（60%）与自一致性（40%）；安全性检测滥用请求是否被正确拒绝；
公平性检测回答中的性别、地域、残疾歧视表述；鲁棒性依赖自一致性采样或默认
基线分；隐私保护检测回答是否泄露 PII；伦理合规检测合法咨询是否被过度拒绝。
各维度均附带可展开的证据说明，前端以雷达图与维度明细呈现。

【LawValidityService 法律时效性】结合 law_registry.json 与 law_repeals.json，
在法条溯源与引用核验中标注「现行有效」或「已废止 · 参见民法典」等状态；
引用废止法律时气泡角标附加「含废止法条」提示。

【DocumentExtractor 文档解析】支持用户上传 txt/md/docx/pdf 及图片（OCR），
提取文本后与 RAG 法条一并注入模型上下文，用于合同审查、文书分析等场景。

【Web 前端】提供登录认证、法律协议确认、多轮会话管理（localStorage 按用户
隔离）、个人资料与头像、收藏与反馈、可信评估报告导出、文档上传、流式问答、
法律类回复的可信评估/法条溯源/引用核验三栏详情、隐私确认与滥用拒答交互，
以及非法律回复的简化展示策略。

================================================================================
五、项目功能详细介绍
================================================================================

法信通的核心能力可以概括为「可信法律问答」「用户文档辅助分析」与「多维在线
评估」三条主线。

在可信法律问答方面，系统从 data/raw 下的法律 Markdown 文件出发，经 convert_md_to_json
解析为带层级结构的 JSON，再经 build_knowledge_base 脚本向量化写入 ChromaDB。
用户提出法律问题时，bge-base-zh 嵌入模型在向量库中检索 Top-K 相关法条，以
编号参考块形式注入 Qwen2.5 的上下文。模型被约束只能引用参考法条中的原文，并
以固定三段式结构输出，从而使用户获得可核对、可溯源的法律信息参考。

引用核验闭环是法信通区别于普通 RAG 系统的关键。CitationExtractor 用正则从大模型
输出中抽取《法律名称》第X条形式的显式引用；ContentVerifier 在知识库中校验
条号是否存在，并通过 ROUGE、余弦相似度等指标判断引用内容与库内原文是否吻合，
article_text 模块支持条/款/项级解析与错条号语义匹配；ImplicitClaimVerifier 则
对未显式引用但含有法律判断的句子做向量检索与 NLI 支撑判断。综合核验分数低于
0.65 时，系统将核验反馈附加到用户问题后触发一次重生成。废止法律引用会附加
时效性警告，前端以标红/标黄区分严重程度。

意图路由与查询重写解决的是实际使用中的两类体验问题。当用户输入「你好」或
「今天天气怎么样」时，系统不再强行检索法条并输出民法典条文，而是以法信通
助手的身份简短回应，并引导用户提出法律问题。当用户输入「身份证110101********1234
被辞退」时，查询重写会去除 PII 噪声并将检索词扩展为「违法解除劳动合同 经济
补偿 劳动仲裁」等，同时在生成 prompt 中强调用户核心诉求是「辞退维权」而非
「证件扣押」，并在偏题时自动纠偏重生成。

输入守卫层面向安全与隐私合规。滥用类问题在前后端均被拦截；含手机号的问题
需用户二次确认；含身份证号的问题自动脱敏后再进入流水线。

Web 端用户体系采用测试阶段固定账号（root/123456）+ Token 认证，前端门禁控制
访问，会话/收藏/个人资料均存浏览器 localStorage。用户可上传合同文书辅助分析、
收藏法律问答、对回复点赞/点踩反馈、导出 HTML 格式可信评估报告。

多维可信评估在每次法律类回答完成后自动运行（流式模式下先出快速分，异步核验
完成后更新），输出 0–100 的综合可信分及高/中/低可信等级建议。

离线方面，scripts/demo.py 支持命令行单轮问答，run_legal_trust_benchmark.py
支持对 LegalTrustBench 进行 no_rag / rag / full 等模式对比评测。

七、启动与部署简要说明
================================================================================

1. 安装依赖：pip install -r requirements.txt
2. 配置 API Key（默认 API 模式）：复制 .env.example 为项目根目录 .env，填写 DASHSCOPE_API_KEY
   （阿里云百炼控制台 → API-KEY 管理；新模型各赠送 100 万 token 免费额度，90 天有效）
3. 数据准备：python scripts/convert_md_to_json.py
4. 构建向量库：python scripts/build_knowledge_base.py（或 demo/minimal 版本；仅需 bge 嵌入模型，无需 GPU）
5. 启动服务：python scripts/run_server.py（或一键启动：双击根目录 start_server.bat，自动检查依赖/知识库/API Key）
6. 浏览器访问：http://localhost:6006（自动跳转 /ui/index.html）
7. 登录账号：root / 123456（测试阶段固定账号）

【团队测试 / 公网访问（阶段九）】
  1. 服务端启动后，双击根目录 start_tunnel.bat（或手动 cpolar http 6006）建立内网穿透
  2. 将 cpolar 窗口中的公网地址（https://xxxx.cpolar.cn）发送给测试人员
  3. 测试人员零安装：任何设备浏览器打开公网地址 → root / 123456 登录即可使用
     （前端页面与 API 同源，WebSocket 自动适配 wss，无需任何配置）
  4. 详细操作与测试清单见 docs/测试人员运行指南.txt

模型权重需放置于 models/bge-base-zh-v1.5、models/Erlangshen-Roberta-330M-NLI 等目录；
仅本地模式（LLM_PROVIDER=local）需要 models/Qwen2.5-7B-Instruct（约 14GB）。
修改 src/config.py 可调整检索相关度阈值、可信权重、是否启用意图路由与查询重写、
LLM_PROVIDER（"api" 百炼 / "local" 本地）等。
