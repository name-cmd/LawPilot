一、项目概述
================================================================================

法信通（LawTrust）是面向中文法律场景的可信智能问答与多维可信评估平台，
以「法条级事实可追溯」为核心目标。平台以阿里云百炼 API 大模型为生成底座
（默认 qwen3.7-plus，共 7 款模型可选；亦可切换本地 Qwen2.5-7B-Instruct
离线推理），整合检索增强生成（RAG）、三级引用核验、TrustLLM 六维可信框架
本地化评估、用户文档解析（合同/文书/图片 OCR）与输入安全守卫，形成统一
问答流水线，并通过 FastAPI 后端与 Vue 3 单页前端承载。

法律问答与通用对话的关键差异在于结果的可证实性：法律结论必须对应具体的
现行有效法条，且结论本身需要能够被用户核验。通用大模型依赖参数化记忆生成
回答，存在编造法条、引用已废止法律的风险，难以满足法律场景对准确性的要求。
针对这一问题，法信通将大模型置于完整可信链路中，而非作为答案的终点：
RAG 从内置法律库检索真实法条作为依据；结构化作答约束模型按
【结论】【法律分析】【依据法条】输出；三级引用核验逐条核对模型引用的准确性，
核验未通过自动触发修正重生成；六维可信评估（TrustLLM 框架本地化实现）对
回答进行可信度打分并输出证据说明，供用户审计。

在此基础上，平台引入智能体（Agent）机制，使模型能够按需主动调用工具：
处理多法条交叉问题时自行检索法条，面对时效问题时直接查询废止注册表，收到
合同文档时转入专用审查管线。大模型与智能体的融合方式及收益详见第二章。

核心能力分三条主线：
  1. 可信法律问答：RAG 检索 + 强制结构化输出 + 三级引用核验 + 时效性标注，
     回答全程可溯源、可审计；
  2. 用户文档辅助分析：上传合同、借条、文书或图片，系统自动识别「合同审查」
     等任务，输出结构化风险清单，并对回答中引用的文档原文做逐字核验；
  3. 多维在线评估：流式快速出分 + 后台异步核验，六维可信评分全程可审计，
     弱维度可展开查看证据与公式。

二、大模型与智能体（Agent）的融合
================================================================================

本章说明智能体的引入动机、实现方式与收益。

【融合动机：从被动问答到主动工具调用】

常规 RAG 问答为线性流程：用户提问 → 系统检索法条 → 连同问题注入模型上下文
→ 模型组织回答。该流程的局限在于，模型只能使用第一轮检索结果，无法在材料
不足时自行补充。智能体机制赋予模型工具调用能力：当模型判断现有材料不足以
作答时，可主动调用 search_articles 检索法条，或调用 check_law_validity
查询法律时效状态，取得结果后继续作答，直至信息充分。

【任务调度：主管-专家模式】

流水线入口处设置任务调度器（src/agents/task_scheduler.py），以确定性规则
将法律问题分为三类：
  - legal_qa（普通法律问答）：走通用问答管线，必要时启用工具调用；
  - contract_review（合同审查）：携带文档且含审查信号时触发，输出
    【合同风险清单】与【总体评价】；无文档但有明确审查意图时引导用户上传；
  - validity_check（时效查询）：直查法律时效注册表得出确定性结论，模型
    仅负责组织语言，不参与时效事实的推断。

分类采用确定性规则而非大模型判断，原因如下：规则匹配毫秒级完成、无额外
模型调用、行为可预期、可单元测试；规则未命中时回退至普通法律问答，最坏
情况与升级前一致，保证功能不退化。

【工具调用：能力开放与回退保障】

工具集收敛为两个本地工具：search_articles（检索法条）与 check_law_validity
（查询时效）。收敛原因在于：工具数量增加会提高模型选错工具、填错参数的概率，
并增加核验难度；两个工具恰好覆盖「多法条交叉比对」与「时效确认」两个高频
场景。工具循环设硬性上限（默认 3 轮，每轮决策 token 上限 512），防止死循环
与费用失控；循环任一步异常（网络错误、参数错误、本地引擎不支持函数调用）
自动降级为普通生成路径，不返回空白或半截回答，失败步骤仍记录于工具轨迹。

工具调用为能力开放而非强制：是否调用、调用何种工具由模型自主决策；普通
问题不触发工具调用时，行为与升级前一致。系统亦不做模型自动路由——智能体
仅决定回答路径（管线选择与工具调用），模型选择始终由用户控制，全链路透明
可解释。

【融合收益】

  1. 专业化分工：合同审查、时效查询各有专用管线，输出结构适配任务类型，
     回答针对性更强；
  2. 时效确定性：时效查询直查注册表，结论由数据决定而非模型记忆，秒级
     返回并标注「来源：法律时效注册表」；
  3. 可核验性增强：工具检索到的法条并入引用核验视野，回答中引用用户文档
     原文的部分逐字比对（document_quotes），工具轨迹全程记录并可视化——
     工具扩展模型的信息视野，最终输出仍受核验约束；
  4. 零回归：离线基准对比（scripts/run_legal_trust_benchmark.py
     --mode agent vs full）显示，开启工具能力后平均可信分与引用核验通过率
     持平（83.2 vs 83.29、0.7 vs 0.7）。

综上，法信通在开放模型工具能力的同时，以核验闭环约束输出质量，形成
「模型自主决策、输出全链路核验」的可信智能体形态。

================================================================================
三、技术栈
================================================================================

【大模型引擎（多模型注册表，src/llm/model_registry.py）】
  - 默认走阿里云百炼 API（OpenAI 兼容），7 款模型可选：
    qwen3.7-plus（默认，Auto 跟随）/ qwen-turbo / qwen3.7-max /
    deepseek-v4-flash-0731 / deepseek-v4-pro / kimi-k2.6 / glm-5.2
  - 本地模式（LLM_PROVIDER=local）：Qwen2.5-7B-Instruct（HuggingFace
    Transformers 推理，fp16 约 14GB 显存，需 CUDA GPU；仅 CLI demo.py 支持，
    Web 端离线调用暂缓）
  - 模型按请求透传（并发不串模型），自一致性核验自动沿用所选模型
  - 嵌入模型：bge-base-zh-v1.5（中文法律条文语义检索，本地，CPU 可跑）
  - NLI 模型：Erlangshen-Roberta-330M-NLI（隐性法律论断支撑判断，本地，CPU 可跑）

【检索与存储】
  - 向量数据库：ChromaDB（持久化目录 law_db/）
  - 法律数据：data/raw 下现行法律 Markdown 源文件 + 废止法律注册表
    （law_registry.json / law_repeals.json，注册表驱动时效查询，不硬编码）
  - 每用户数据：data/users/ 下 JSON 文件（注册表 / Token 表 / 每用户会话收藏，不入库）

【后端服务】
  - Web 框架：FastAPI + Uvicorn（默认端口 6006）
  - 流式传输：SSE（/api/chat/stream）+ WebSocket（/ws/verification/{message_id}）
  - 鉴权：Token 认证（24h 滑动过期、多端共存、重启恢复），密码 pbkdf2 哈希
  - 数据校验：Pydantic v2；运行环境：Python 3.x（API 模式无需 GPU）

【前端演示】
  - 单页应用：Vite + Vue 3（script setup）+ TypeScript + Tailwind CSS v4
    + Naive UI + Pinia 持久化
  - 图表可视化：ECharts（六维可信雷达图，按需引入）
  - 本地存储：localStorage（登录态、会话、收藏、个人资料，按用户名隔离）
  - 服务端双写同步：登录拉取恢复 + 3 秒防抖整包提交（useSync.ts）

【文档处理】
  - 支持格式：txt、md、docx、pdf、jpg/png/bmp/tiff/webp 图片（OCR）
  - OCR 引擎：rapidocr（可配置 paddleocr）
  - 单文件上限 10MB，最多 5 个附件，注入上下文最多 12000 字符

【评测与工具】
  - 单元测试：pytest（tests/ 下 11 个测试文件，66 例通过）
  - 离线基准：LegalTrustBench + run_legal_trust_benchmark.py
    （--mode no_rag/rag/full/agent 对比评测）
  - 命令行 Demo：scripts/demo.py（API 模式；本地模式需 GPU）
  - 一键部署：start_server.bat（服务端一键启动）+ start_tunnel.bat（内网穿透）

五、主要模块说明
================================================================================

【AnswerPipeline 问答流水线】整个系统的调度中枢。用户问题先经意图路由器
判断属于法律咨询、寒暄问候、通用非法律还是文档分析场景，再分派到对应处理
路径：
  - 寒暄 / 通用非法律：切换专用 system prompt，不注入 RAG 结果，不执行引用
    核验与可信评分，Web 端同步隐藏评估详情，避免为低价值问题消耗算力；
  - 法律咨询：查询重写模块先剥离身份证号、手机号等噪声词，再按「辞退」「欠
    薪」等关键词扩展检索查询；多路向量检索仅保留相关度高于阈值（默认 0.35）
    的法条注入上下文；模型按【结论】【法律分析】【依据法条】结构作答后，
    CitationVerifier 做三级核验，分数低于阈值自动重生成一次；
  - 文档分析（上传文档 + 提问不含法律关键词）：跳过 RAG，使用文档分析专用
    提示词客观总结文档要点，不套三段式，不罗列无关法条。

流式模式下，系统先通过 SSE 快速输出首版回答与初步可信分，随后在后台异步
执行完整引用核验与六维评分，结果经 WebSocket 推送给前端动态更新，兼顾响应
速度与评估完整性。

【智能体 Agent】在 legal_qa 意图内做任务细分与工具编排，设计思路见第二章：
  - 任务调度器（task_scheduler.py）：确定性规则把法律问题分为三类——
    legal_qa（普通问答）、contract_review（合同审查：携带文档 + 审查信号，
    输出【合同风险清单】+【总体评价】结构化结果；无文档强审查意图则引导上
    传）、validity_check（时效查询：直查 law_registry.json 注册表出确定性
    结论）；
  - 工具调用引擎（agent_loop.py + tools.py）：2 个 function calling 工具
    （search_articles 检索法条 / check_law_validity 查询时效），循环上限 3
    轮，每轮决策 token 上限 512；本地引擎自动降级普通生成，失败兜底不中断；
  - 工具轨迹（trace.py）：每轮工具名/参数/结果摘要/耗时记录进 tool_trace，
    SSE 以 agent_status 事件实时推送，前端「工具轨迹」面板可视化展示；
  - 文档引文核验（document_quotes.py）：对回答中引用用户文档原文的部分
    （“…”/「…」/《…》三种引号样式）逐字比对，防止模型编造合同条款被误当
    文档事实。

【InputGuard 输入守卫】在 Web 提交与 API 层双重生效。对伪造证据、逃避法律
责任、洗钱等滥用模式直接拒答且不调用大模型；对身份证号、银行卡号等极度敏感
信息自动脱敏；对手机号、详细地址等一般隐私信息弹出确认框，用户确认后才发送。
拒答以「安全拦截」样式展示，不参与可信评估。

【LegalTrustScorer 六维可信评分】TrustLLM 框架的本地化实现：真实性（引用核验
准确率 60% + 自一致性 40%）、安全性（滥用请求拒绝检测）、公平性（性别/地域/
残疾歧视检测）、鲁棒性（自一致性采样或默认基线）、隐私保护（PII 泄露检测）、
伦理合规（合法咨询是否被过度拒绝）。各维度附带可展开的证据说明，前端以雷达
图、加权贡献条与审计明细呈现，评分过程全程可追溯。

【LawValidityService 法律时效性】以 law_registry.json 与 law_repeals.json 为
数据源（注册表驱动，新增废止法律无需改代码），在法条溯源与引用核验中标注
「现行有效」或「已废止 · 参见民法典」等状态；引用废止法律时气泡角标附加
「含废止法条」提示；时效查询任务（validity_check）直接由注册表给出确定性
结论。

【DocumentExtractor 文档解析】支持 txt/md/docx/pdf 及图片（OCR）解析，提取
文本与 RAG 法条合并注入模型上下文，用于合同审查、借条分析等场景；解析中/
解析失败均有前端状态提示，附件最多 5 个、单文件 10MB、上下文 12000 字符。

【多用户账号体系（阶段三）】账号数据（会话/收藏/资料/自配 API Key）存服务端
data/users/ 下 JSON 文件：密码 pbkdf2 哈希、Token 24h 滑动过期、多端共存、
重启恢复；种子账号 root/user1/user2（密码均 123456），登录页可注册新账号。
每账号可自配百炼 API Key：请求带 token 时后端解析用户 Key 沿
pipeline → model → api_client 透传（按 base_url+api_key 缓存客户端，并发不
串 Key），未配置回退服务端 .env Key。前端按用户名隔离本地数据，登录拉取恢复、
3 秒防抖整包提交双写同步。

【Web 前端】三栏布局（会话栏/对话区/详情面板）：登录注册与法律协议确认、
多模型选择器（Auto + 7 模型 + 品牌 logo）、设置面板六区（通用 / 模型与推理 /
检索与引用 / 可信评估 / 隐私与安全 / 数据管理）、会话管理（自动命名/重命名/
删除/清空）、流式问答与异步核验、右侧详情四面板（可信评估/法条溯源/引用核验/
工具轨迹）、消息操作（点赞/点踩/复制/重新生成/收藏）、个人资料与收藏管理、
输入守卫交互（安全拦截/隐私确认/脱敏提示）、智能体状态行与时效来源标注。

六、登录使用与环境配置
================================================================================

【访问方式】
  1. 启动服务：python scripts/run_server.py（或双击根目录 start_server.bat）
  2. 浏览器访问 http://localhost:6006（自动跳转 /ui/index.html）

【账号体系（阶段三）】
  - 种子测试账号：root / 123456、user1 / 123456、user2 / 123456
    （每个账号的会话/收藏/资料互相隔离，登录后自动从服务端恢复）
  - 注册新账号：登录页底部「立即注册」→ 用户名（3-20 位字母/数字/下划线，
    首字符为字母或下划线）+ 密码（至少 6 位）→ 注册成功即自动登录
  - 退出登录：右上角账号菜单 →「退出登录」；重新登录后数据自动恢复
  - 会话有效期：Token 24 小时滑动续期，多设备可同时登录

【API Key 配置（按账号）】
  - 全局默认：根目录 .env 中 DASHSCOPE_API_KEY=sk-xxx（参考 .env.example）
  - 每账号自配：设置面板「模型与推理」区 → 输入个人 Key → 保存；
    该账号后续请求优先使用个人 Key，未配置时回退服务端 .env Key
  - 修改密码：设置面板「隐私与安全」区（改密后其他设备 Token 自动吊销）；
    清空个人数据：设置面板「数据管理」区

【模型选择】
  - 输入框旁模型选择器：两级选择——「离线调用」/「API 调用」
  - API 调用下：Auto（跟随设置面板全局默认模型，默认 qwen3.7-plus）或 7 款
    具体模型之一；模型名/品牌 logo 随选择变化，自一致性核验沿用所选模型
  - 离线引擎需 CUDA GPU + models/ 权重，未就绪自动置灰并提示原因

【问答选项（设置面板「检索与引用」区）】
  - RAG 法条检索（默认开启）：控制是否从向量库检索并注入法条
  - 自一致性评估：多次采样评估鲁棒性，开启后耗时增加
  - NLI 引用核验（默认开启）：隐性法律论断的 NLI 支撑判断
  - 自一致性采样次数：2 / 3 / 5 次可选

【测试与演示数据】
  - 文档上传测试材料位于 docs/测试文件/（合同案例 1/2、借条.txt、借条图片.png、
    技术说明文档.txt），详细测试用例见《法信通_Web端功能展示清单.txt》

七、启动与部署简要说明
================================================================================

1. 安装依赖：pip install -r requirements.txt
   （API 模式无需 CUDA GPU；本地模式需 GPU + 下载模型权重，见根目录 download*.py）
2. 配置 API Key：复制 .env.example 为项目根目录 .env，填写 DASHSCOPE_API_KEY
   （阿里云百炼控制台 → API-KEY 管理获取；新模型各赠送 100 万 token 免费额度，
   90 天有效）
3. 数据准备：python scripts/convert_md_to_json.py
4. 构建向量库：python scripts/build_knowledge_base.py
   （或 demo/minimal 版本；仅需 bge 嵌入模型，无需 GPU）
5. 启动服务：python scripts/run_server.py
   （一键启动：双击 start_server.bat，自动检查依赖/知识库/API Key/端口占用）
6. 浏览器访问：http://localhost:6006，用 root/123456（或注册新账号）登录
7. 命令行验证：python scripts/demo.py --query "劳动合同解除需要提前多少天通知？"
   （API 模式；LLM_PROVIDER=local 切本地 7B 推理，需 GPU + 权重）

【团队测试 / 公网访问（阶段九）】
  1. 服务端启动后，双击根目录 start_tunnel.bat（或手动 cpolar http 6006）
     建立内网穿透
  2. 将公网地址（https://xxxx.cpolar.cn）发送给测试人员
  3. 测试人员零安装：任何设备浏览器打开公网 URL → root/123456 登录即可
     （前端与 API 同源，WebSocket 自动适配 wss，无需配置）
  4. 详细操作与测试清单见 docs/测试人员运行指南.txt

【配置中心】修改 src/config.py 可调整：检索相关度阈值（默认 0.35）、可信权重、
RAG/自一致性/NLI 开关、LLM_PROVIDER（"api"/"local"）、DEFAULT_API_MODEL、
智能体开关（AGENT_ENABLE_TOOLS / AGENT_MAX_TOOL_ROUNDS）、Token 有效期
（SESSION_TTL_SEC）等；.env 中的 DASHSCOPE_API_KEY、DEFAULT_API_MODEL 优先。

【离线评测】
  - 命令行 Demo：python scripts/demo.py --query "问题"
  - 基准评测：python scripts/run_legal_trust_benchmark.py --mode full --mock
    （--mode 支持 no_rag / rag / full / agent，agent 模式对比智能体工具调用效果）
  - 单元测试：pytest tests/ -q（66 例）
